# BIRDSSKY — GAME WORD BANK AND SCORING SPECIFICATION
# Dataset audit: 430 objects; answer counts vary by object (9–13 in this file).
# The original 330-object import is followed by 100 appended objects (source noted below).
# All category score values are preserved exactly from the supplied source; this pass does not invent new scores.
# Score bands: Common 100–199; Rare 200–399; Extreme 400–599; Eagle 600–800. Score 0 means invalid.
# Altitude conversion: altitude_units = score * 0.12 (100 points = 12 units); do not round unless the game UI requires it.
# Category counts are not fixed: do not assume every object has exactly ten answers.
#
# RECOMMENDED ANSWER-VALIDATION RULES
# 1. A category must be a real, recognizable class/type that the object itself belongs to.
#    A mere association, use, location, audience, material, component, or setting is not enough.
# 2. Judge the object's ordinary/default form. Do not assume a material, feature, or use not stated in the prompt.
# 3. Rarity is not the same as technicality. Long, obscure-sounding, or highly qualified phrases do not earn points by themselves.
# 4. A category must be independently established and meaningful; reject invented taxonomies, word salad,
#    arbitrary adjective combinations, tautologies, and categories that only describe one possible instance.
# 5. A narrower category is eligible only when it is a recognized subclass and the object genuinely qualifies.
#    Do not reward a phrase merely because it adds constraints (e.g. colour, location, owner, or imagined context).
# 6. Score a valid answer using its object-specific canonical entry. Do not generate a fresh score at runtime.
#    The same category may have different scores for different objects only if the scoring design intentionally
#    measures rarity relative to that particular object; keep this object-specific rule consistent.
# 7. Normalize harmless formatting differences (case, leading/trailing spaces, repeated spaces, hyphenation).
#    Treat synonyms, abbreviations, and spelling variants as aliases only when explicitly approved in an alias list.
# 8. If an answer is not in the bank but appears valid, send it to review rather than letting an AI invent a score.
#    Add approved answers to the bank with a documented score before awarding points.
# 9. Invalid, unrelated, unsupported, or fabricated categories score 0. Never clamp an invalid answer to 100.
# 10. Do not infer a score from the tier label alone; use the exact numeric value attached to the accepted category.
# 11. Before release, test each object with ordinary players and record how often each category is independently named.
#     Use those response rates to recalibrate rarity scores; treat the current values as provisional editorial scores,
#     not measured population frequencies, unless the source data proves otherwise.
#
# DATA-INTEGRITY NOTES
# - The supplied file contains 430 objects, not 330.
# - Category counts vary from 9 to 13; the old 'all ten answers' claim was inaccurate.
# - 'Common' is used as the normalized field name throughout (the source had two heading variants).
# - The dataset is structurally parseable: every category entry has a numeric score in its stated score band;
#   no duplicate category names were found within an individual object.
# - Some objects intentionally/incidentally have no Eagle entry or no Extreme entry; absence is not a zero-score answer.
#
